# PhotoPainter (B) 产品分析与实现依据

## 功能目标

- 在产品自带 Pico 主控上运行 Python，采用 MicroPython；电脑只用于开发、上传和可选的素材制作。
- 从 TF 卡读取图片或 UTF-8 TXT/Markdown，使用五字段 cron 加文件路径排程。
- 使用产品已有电池和外部 RTC 低功耗唤醒；中英文显示；重启恢复最近事件内容。
- TXT/Markdown 首次生成同目录像素缓存；支持居中标题、粗体及六色文字；日志按日期统一保存，以最低级别过滤串口和文件。
- NEXT 短按显示当前时间、上次充满时间、待机时长及电压/百分比，60 秒后恢复排程；长按 3 秒按 cron 行序检查所有素材，每项显示 60 秒。

- 官方代码：https://github.com/waveshareteam/PhotoPainter_B ，分析与驱动移植基于提交 `fc2b261e985934bf67d99aa26358e463deb0aa65`。
- 官方示例包 `PhotoPainter_B.zip`：CMake、屏幕驱动及引脚定义与上述 GitHub 版本的有效文本一致；`main.c` 默认定时为 5 分钟，GitHub 版为 12 小时。部分字节差异来自行尾格式。
- 屏幕模块手册 `7.3inch-e-Paper-(E)-user-manual.pdf`：版本 1.0，2024-07-10；描述屏幕参数，不单独作为整机电池容量、接口或主控型号的依据。
- MicroPython 官方仓库提供 `ports/rp2/boards/RPI_PICO2` 板型，micropython-lib 提供 SPI SD 卡驱动。本项目语言验证版本为 v1.26.0。

## 可核实的硬件和接口

| 项目 | 结果与依据 |
| --- | --- |
| 屏幕 | 7.3 英寸，800×480，有效区域 160×96 mm；PDF 第 3 页 |
| 颜色 | 黑、白、黄、红、蓝、绿；PDF 与 `EPD_7in3e.h` 一致 |
| 板型 | RP2350/Pico 2；官方 CMake 设置 `PICO_BOARD pico2`，SDK 2.0.0，当前实机运行正常 |
| 屏幕接口 | SPI1，SCK GP10，MOSI GP11，CS GP9，DC GP8，RST GP12，BUSY GP13 |
| TF 卡接口 | SPI0，SCK GP2，MOSI GP3，MISO GP4，CS GP5 |
| 外部 RTC | PCF85063，I2C1，地址 0x51，SDA GP14，SCL GP15，中断 GP6 |
| 电源控制 | GP16 屏幕电源使能；GP18 高电平保持电池供电、低电平请求断电 |
| 按键与充电 | GP19 为按键/电池状态输入，GP17 为充电状态，GP24 为 VBUS 检测 |
| 电池检测 | GP29/ADC3；官方算法使用 ADC 电压乘 3，需实物校准 |
| LED | GP25 活动指示，GP26 电源/充电指示 |

以上引脚来自 `lib/Config/DEV_Config.h` 和初始化代码，GP 编号不是排针物理序号。官方示例未提供网络功能，不能假定产品内置 Wi-Fi 或蓝牙。

## 官方程序实际行为

1. 初始化接口、RTC 和电源保持，检查电池电压。
2. 挂载 TF 卡，默认扫描 `pic/`，对图片路径排序，通过 `index.txt` 保存轮播位置。
3. 按 BMP 路径读取图像，显示后更新索引，并使屏幕进入休眠。
4. 电池供电分支显示一次后调用 `powerOff()`。充电分支循环处理充电状态和按键，默认 `enChargingRtc=0`。
5. `extra_uf2` 提供 15 分钟至 24 小时等间隔版本；说明文件明确下一轮计时在刷新完成后开始，因此不是严格的墙上时钟日程。
6. 示例启动时使用硬编码的 2024-03-31 设置 RTC。日程指示牌不能直接沿用这段时间初始化，应保留真实时间、检查时间有效性，并提供校时入口。

## AUTO-NEXT 开关与 RTC

官方知识库页面截图说明：AUTO-NEXT 默认 OFF 时不响应 RTC；ON 时由 RTC 触发自动切换，官方默认间隔 12 小时，NEXT 按键仍有效。

GitHub 官方提交 `fc2b261e985934bf67d99aa26358e463deb0aa65` 和官方示例包 `PhotoPainter_B.zip` 均有以下代码：

- `lib/Config/DEV_Config.h` 定义 `RTC_INT=6`、`BAT_OFF=18`、`BAT_STATE=19` 和 `Power_Mode=23`。
- `DEV_Config.c` 将 GP6 配为输入并上拉；将 GP18 输出置高以保持电池供电。
- `main.c` 启动时设置 RTC 闹钟，电池分支显示一次后通过 GP18 请求关机；USB 循环中的 RTC 低电平检测由 `enChargingRtc` 编译选项控制，示例默认为 `0`。该编译选项不表示物理开关档位。
- GP19 低电平用于检测 NEXT。`Power_Mode` 只有定义，没有初始化或读取；两个来源均未找到读取 AUTO-NEXT ON/OFF 档位的实现。

代码与截图共同支持“开关可能通过硬件控制 RTC 自动唤醒通路”的推断，但不能确定具体接线或断言可从某个 GPIO 直接读取档位。需原理图或实机测量确认，不能仅凭 `Power_Mode` 的名称把 GP23 当作开关输入。

当前 MicroPython 电池模式依赖 RTC 唤醒通路，自动排程时应将开关置 ON。USB 模式通过读取 RTC 时间和 cron 主动调度，尚无按此物理开关档位暂停排程的代码；读取 GP6 只能获知 RTC 信号，不能直接表示 AUTO-NEXT 档位。

## MicroPython 实现约束

- 官方产品示例使用 C。本项目已移植屏幕初始化、SPI 传输、BUSY 等待、RTC、SD 卡和电源管理至 MicroPython。
- 屏幕像素编码为黑 0、白 1、黄 2、红 3、蓝 5、绿 6；编码 4 不作为本屏支持颜色使用。两个像素打包为一个字节，左像素占高四位，单帧需 192,000 字节。
- 整帧 RGB 数据需 1,152,000 字节。本项目复用一个 192,000 字节打包帧缓冲，分块读取图片与缓存，避免分配第二个整帧缓冲。
- 中文采用 TF 卡上的思源黑体点阵字库，按需读取，字形缓存最多 8 KiB；文字排版与绘制在设备上执行，字体和图片转换工具在电脑上运行。
- 官方 BMP 读取器只识别六种精确 RGB 值，未完整处理通用 BMP 的行填充和其他颜色。本项目支持 800×480、未压缩 24 位 BMP 的行填充及颜色映射，另支持打包六色 E6 文件。
- BUSY 低为忙，驱动包含等待超时和失败处理。屏幕命令以官方工作驱动为基线，显示已在实机日常使用中验证。
- 常规排程仅在内容变化时执行全屏刷新；素材检查模式逐行刷新。既有 USB 实机日志测得屏幕刷新约 19.09 秒，具体耗时与运行条件有关。
- 电池模式通过 GP18 保持供电，设置 RTC 闹钟后请求断电，由 RTC 信号重新上电执行程序。该流程已在实机定时运行中验证；日常排程等待采用整机关机，状态页、素材预览及 USB 等待期间保持主控供电。
- 首次刷写、上传和调试推荐 USB 供电；刷入 MicroPython 会替换现有应用固件，应先准备对应官方 UF2 和明确恢复步骤。
- TF 卡使用已验证的 FAT32 配置；exFAT 未列入当前支持范围。

## 验证方法

1. 主机自动化测试检查排程与时间计算、排版与缓存、日志、按键、充电记录及模拟硬件交互。
2. MicroPython v1.26.0 Unix 在 320 KiB 堆限制下检查语言兼容、帧缓冲复用和完整素材处理。
3. PhotoPainter (B) 实机检查显示、按键、日志、指示灯、电池供电与 RTC 唤醒，并通过日常使用观察运行状态。
4. 低电量至再次充满电的完整循环检查电池图标、低压关机、充满时间记录和待机累计；当前尚未完成这一项实机验证。

## 实现与验证状态

已实现主控端 MicroPython 程序、cron 文件路径排程、中英文 TXT/基础 Markdown、最终像素缓存、六色文字、BMP/打包六色图片、RTC 闹钟、电池关机及重启恢复、日期日志、NEXT 四行状态页与长按素材检查。采用横屏 800×480，可选 0/180° 方向。

截至 2026-10-13，已投入实机日常使用，显示与排版、排程、RTC 校时与电池定时唤醒、缓存、状态页与长按素材检查、日志及运行状态指示目前正常。已通过 97 项自动化测试和 320 KiB 堆的 MicroPython Unix 验证。

低电量图标、低压关机提醒，以及再次充满电后的时间记录和待机累计已通过自动化验证，尚待完整电池循环实测；目前没有完整放电周期的续航或电量曲线标定数据。各项验证状态见 [README](../README.md#程序与验证)。
