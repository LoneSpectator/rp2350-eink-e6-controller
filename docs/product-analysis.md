# PhotoPainter (B) 产品分析与待确定需求

## 已确定的目标

- 在产品自带 Pico 主控上运行 Python，采用 MicroPython；电脑只用于开发、上传和可选的素材制作。
- 用户随后确定：TF 图片或 UTF-8 TXT，用五字段 cron 加文件路径排程。
- 使用产品已有电池和外部 RTC 低功耗唤醒；中英文显示；重启恢复最近事件内容。
- 后续确定：TXT/Markdown 首次生成同目录像素缓存；居中标题、粗体及六色文字；可配置调试与长期异常日志，串口带时间/级别；NEXT 临时状态页显示时间、运行时长和电池信息，60 秒后恢复最新排程。

## 可核实的硬件和接口

| 项目 | 结果与依据 |
| --- | --- |
| 屏幕 | 7.3 英寸，800×480，有效区域 160×96 mm；PDF 第 3 页 |
| 颜色 | 黑、白、黄、红、蓝、绿；PDF 与 `EPD_7in3e.h` 一致 |
| 板型 | 官方 CMake 设置 `PICO_BOARD pico2`，SDK 2.0.0；指向 RP2350/Pico 2，刷机前仍需确认实物型号 |
| 屏幕接口 | SPI1，SCK GP10，MOSI GP11，CS GP9，DC GP8，RST GP12，BUSY GP13 |
| TF 卡接口 | SPI0，SCK GP2，MOSI GP3，MISO GP4，CS GP5 |
| 外部 RTC | PCF85063，I2C1，地址 0x51，SDA GP14，SCL GP15，中断 GP6 |
| 电源控制 | GP16 屏幕电源使能；GP18 高电平保持电池供电、低电平请求断电 |
| 按键与充电 | GP19 为按键/电池状态输入，GP17 为充电状态，GP24 为 VBUS 检测 |
| 电池检测 | GP29/ADC3；官方算法使用 ADC 电压乘 3，需实物校准 |

## 官方程序实际行为

1. 初始化接口、RTC 和电源保持，检查电池电压。
2. 挂载 TF 卡，默认扫描 `pic/`，对图片路径排序，通过 `index.txt` 保存轮播位置。
3. 按 BMP 路径读取图像，显示后更新索引，并使屏幕进入休眠。
4. 电池供电分支显示一次后调用 `powerOff()`。充电分支循环处理充电状态和按键，默认 `enChargingRtc=0`。
5. `extra_uf2` 提供 15 分钟至 24 小时等间隔版本；说明文件明确下一轮计时在刷新完成后开始，因此不是严格的墙上时钟日程。
6. 示例启动时使用硬编码的 2024-03-31 设置 RTC。日程指示牌不能直接沿用这段时间初始化，应保留真实时间、检查时间有效性，并提供校时入口。

## MicroPython 实现约束

- 官方产品示例是 C，不是现成 MicroPython 应用。需要移植屏幕初始化、SPI 传输、BUSY 等待、RTC、SD 卡和电源管理。
- 屏幕像素编码为黑 0、白 1、黄 2、红 3、蓝 5、绿 6；编码 4 不作为本屏支持颜色使用。两个像素打包为一个字节，左像素占高四位，单帧需 192,000 字节。
- 整帧 RGB 数据需 1,152,000 字节，不适合放进 Pico 的 Python 堆；优先使用一个打包帧缓冲或分块读取预生成素材，并在实机测量可用堆和最大连续分配。
- 中文显示需要字体资源；优先考虑按所需字符制作点阵字库或预生成文字素材。设备端绘制逻辑仍由 MicroPython 执行，是否允许电脑准备素材待确定。
- 官方 BMP 读取器只识别六种精确 RGB 值，检查 24 位格式后仍继续读，不完整处理通用 BMP 的行填充和其他颜色，并有特定方向映射。新实现需明确支持的尺寸、色深、方向和格式，不直接照搬。
- PDF 指出 BUSY 低为忙；新驱动应按实际电平等待，设置超时并处理失败。源码和 PDF 部分命令参数/注释有差异，移植应以官方工作驱动为基线，通过实机确认。
- 当前材料未给出可据以承诺的实际刷新时长、局部刷新能力、最小刷新间隔和整机续航。先采用内容变更后全屏刷新，避免秒级动画需求，后续按实机测量确定刷新策略。
- 电池模式的 RTC 唤醒涉及整机电源电路，不能靠 Python 的 sleep 等价替代。需先验证 MicroPython 启动时 GP18 的供电保持，再验证 RTC 中断能唤醒并重新执行程序。
- 首次刷写、上传和调试推荐 USB 供电；刷入 MicroPython 会替换现有应用固件，应先准备对应官方 UF2 和明确恢复步骤。
- 新项目优先使用 FAT32 TF 卡；不要因 C 示例启用了 exFAT 就假定所选 MicroPython 固件具有同样支持。

## 建议的开发与验证顺序

1. 确定场景、真实文案、横竖方向、更新来源、按键行为和供电方式。
2. 选择并固定与实物匹配的 MicroPython UF2；准备 USB 上传与串口调试步骤，不在云端声称已经刷机。
3. 实现独立的板级配置和屏幕驱动，先做六色块、方向标记和 BUSY 超时测试。
4. 验证 SD 挂载、RTC 读取及校时、电池检测和电源保持，再实现应用排版、持久化及刷新策略。
5. 根据场景增加中文、素材、按键切页或日程，加入断电恢复和输入错误处理。
6. 云端测试打包、排版边界、时间计算和模拟硬件交互；用户设备测试实际色彩、方向、刷新时长、按键、电池断电和 RTC 唤醒。两类测试结果分别记录。
